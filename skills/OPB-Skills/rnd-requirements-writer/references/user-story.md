## 基础格式

```
作为 [用户角色]，
我想要 [功能/行为]，
以便 [获得的价值]。
```

## 完整模板

```markdown
# [STORY-XXX] [故事标题]

## 用户故事
作为 **[用户角色]**，
我想要 **[功能/行为]**，
以便 **[获得的价值]**。

## 背景说明
[为什么需要这个功能？解决什么问题？]

## 验收标准
- [ ] AC1: Given [前置条件]，When [用户行为]，Then [期望结果]
- [ ] AC2: Given [前置条件]，When [用户行为]，Then [期望结果]
- [ ] AC3: ...

## 技术备注
[实现相关的技术说明，如涉及的API、数据模型等]

## 界面原型
[链接或描述]

## 依赖项
- [ ] 依赖 [STORY-YYY] 完成
- [ ] 需要 [外部服务/API]

## 标签
- 优先级：P0/P1/P2/P3
- 模块：[模块名]
- 预估：[故事点/天数]
```

## 验收标准写法

### Given-When-Then 格式

```
Given [前置条件/上下文]
When [用户执行的动作]
Then [期望的结果]
```

### 验收标准检查清单

好的验收标准应该：
- [ ] 可测试：能明确判断通过/失败
- [ ] 独立：不依赖其他标准的结果
- [ ] 具体：包含具体数值或状态
- [ ] 完整：覆盖正常流程和边界情况

### 常见验收标准类型

1. **功能验证**：核心功能是否正常工作
2. **边界条件**：极端输入、空值、最大值
3. **错误处理**：异常情况的提示和处理
4. **性能要求**：响应时间、并发要求
5. **安全要求**：权限控制、数据保护

## 拆分技巧

当故事太大时，按以下维度拆分：

### 按工作流步骤
```
原：用户可以完成订单流程
拆：
- 用户可以添加商品到购物车
- 用户可以填写收货地址
- 用户可以选择支付方式
- 用户可以确认并提交订单
```

### 按用户角色
```
原：用户可以管理文章
拆：
- 作者可以创建文章草稿
- 编辑可以审核文章
- 管理员可以发布文章
```

### 按数据类型
```
原：系统支持多种文件上传
拆：
- 用户可以上传图片（JPG/PNG）
- 用户可以上传文档（PDF/DOC）
- 用户可以上传视频（MP4）
```

### 按操作类型（CRUD）
```
原：用户可以管理个人资料
拆：
- 用户可以查看个人资料
- 用户可以编辑个人资料
- 用户可以上传头像
- 用户可以删除账号
```

## 示例

### 示例1：登录功能

```markdown
# [AUTH-001] 用户邮箱登录

## 用户故事
作为 **注册用户**，
我想要 **使用邮箱和密码登录系统**，
以便 **访问我的个人数据和功能**。

## 背景说明
用户需要安全地访问系统，邮箱登录是最基础的认证方式。

## 验收标准
- [ ] AC1: Given 用户在登录页面，When 输入正确的邮箱和密码并点击登录，Then 跳转到首页并显示用户名
- [ ] AC2: Given 用户在登录页面，When 输入错误的密码，Then 显示"邮箱或密码错误"提示
- [ ] AC3: Given 用户连续输错密码5次，When 再次尝试登录，Then 账号被锁定15分钟
- [ ] AC4: Given 用户在登录页面，When 邮箱格式不正确，Then 显示"请输入有效的邮箱地址"

## 技术备注
- 使用 bcrypt 加密密码
- 登录状态使用 JWT token，有效期 7 天
- 记录登录日志（IP、时间、设备）

## 标签
- 优先级：P0
- 模块：认证
- 预估：2天
```

### 示例2：数据导出

```markdown
# [REPORT-005] 导出销售报表

## 用户故事
作为 **销售经理**，
我想要 **将销售数据导出为Excel文件**，
以便 **进行线下分析和汇报**。

## 验收标准
- [ ] AC1: Given 用户在报表页面，When 点击导出按钮，Then 下载包含当前筛选条件数据的Excel文件
- [ ] AC2: Given 数据量超过10000条，When 点击导出，Then 显示进度条，后台异步处理
- [ ] AC3: Given 导出完成，When 文件准备好，Then 发送邮件通知并提供下载链接
- [ ] AC4: Given 数据量为0，When 点击导出，Then 提示"没有可导出的数据"

## 标签
- 优先级：P1
- 模块：报表
- 预估：3天
```
